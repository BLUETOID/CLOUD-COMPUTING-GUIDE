2023–24 · Q1 Unit I 10 Marks

1. Discuss the underlying principles of Parallel Computing. How does it contribute to the performance of cloud applications?
View Full-Mark 10M Answer
1. Definition

Parallel Computing is a computational architecture in which a large problem is decomposed into smaller independent sub-tasks that execute simultaneously across multiple CPU cores or GPUs sharing memory to reduce total execution time.

2. Core Underlying Principles
  1. Problem Decomposition: Breaking work into concurrent units—either Data Parallelism (applying the same operation to different data partitions, e.g., resizing 10,000 images) or Task Parallelism (executing different functions simultaneously, e.g., reading, compressing, and uploading in parallel threads).
  2. Flynn's Taxonomy: Classifies parallel machines into SISD (classic single-core), SIMD (GPUs/vector processors), MISD (fault-tolerant aviation pipelines), and MIMD (modern multi-core cloud servers & clusters).
  3. Synchronization & Communication: Coordinates threads via locks, semaphores, and barriers to avoid race conditions while minimizing synchronization overhead.
  4. Load Balancing: Distributes sub-tasks evenly across all cores so fast cores do not sit idle waiting for overloaded ones.
  5. Amdahl's Law (Speedup Limit): S(N) = 1 / [ (1 − p) + (p / N) ]. The sequential portion (1 − p) limits maximum speedup. Example: If p = 0.80 and N = 4 cores, S(4) = 1 / (0.20 + 0.20) = 2.5× (max 5× even with infinite cores).
3. Contribution to Cloud Application Performance
  • Ultra-Fast Compute & AI/ML: Cloud GPU instances (SIMD/MIMD) train deep-learning models and render 4K video in minutes instead of weeks.
  • High Request Throughput: Multi-core cloud web servers handle thousands of concurrent user sessions with low latency.
  • Big Data Analytics: Frameworks like Apache Spark and Hadoop run thousands of parallel tasks over petabyte datasets.
  • Cost Reduction: Completing batch jobs faster directly lowers pay-per-second cloud bills.
Exam Tip: Always write Amdahl's Law with the p = 0.8, N = 4 → 2.5× calculation and list Flynn's 4 classes (SISD, SIMD, MISD, MIMD). See Unit I SVG Diagrams →

2. Explain the virtualization of CPU in cloud computing. How does it enable multiple virtual machines to run on a single physical processor?
View Full-Mark 10M Answer
1. Definition

CPU Virtualization abstracts a single physical processor (pCPU) into multiple Virtual CPUs (vCPUs) so that several isolated Virtual Machines (VMs) execute concurrently on the same host, each believing it owns dedicated processor cores.

2. CPU Virtualization Architecture Diagram
3. How Multiple VMs Run on One Physical Processor
  1. vCPU Time-Slicing & VMCS: The hypervisor schedules vCPUs in rapid millisecond slices across physical cores, saving each VM's CPU registers in a VMCS (Virtual Machine Control Structure) during context switches.
  2. Direct Execution + Trap-and-Emulate: Normal user-mode instructions run directly on hardware at native speed. Privileged instructions (that alter system hardware) trap to the hypervisor so one guest cannot interfere with another.
  3. Three Core Mechanisms: (a) Full Virtualization (binary translation for unmodified OS), (b) Paravirtualization (modified guest makes direct hypercalls), and (c) Hardware-Assisted Virtualization (Intel VT-x / AMD-V provides VMX root/non-root modes for near-native hardware VM Exits).
4. Cloud Impact

Enables safe CPU overcommitment (e.g., 16 vCPUs on 8 physical cores), raises data center CPU utilization from ~15% to 75%+, and powers multi-tenant compute platforms like AWS EC2 and Azure VMs.

3. Discuss the NIST Cloud Computing Reference Architecture. What are its key components?
View Full-Mark 10M Answer
1. Overview

Published in NIST SP 500-292, the NIST Cloud Computing Reference Architecture is a vendor-neutral conceptual model that defines five major actors (Consumer, Provider, Broker, Auditor, Carrier) and the internal components of a Cloud Provider.

2. NIST 5-Actor Architecture Diagram
3. Key Components (Five Actors + Provider Internals)
  1. Cloud Consumer: Person or enterprise subscribing to cloud services, signing SLAs, and paying metered bills.
  2. Cloud Provider: Builds and operates cloud infrastructure. Internally contains: (a) Service Deployment (Public/Private/Hybrid), (b) Service Orchestration (Service Layer + Virtualization + Physical Layer), (c) Cloud Service Management (Business Support, Provisioning, Portability), (d) Security, and (e) Privacy.
  3. Cloud Broker: Intermediary managing service use across providers via Intermediation (value-added services), Aggregation (combining multiple services), and Arbitrage (choosing the cheapest/best provider dynamically).
  4. Cloud Auditor: Independent third-party assessor auditing security controls, privacy compliance, and SLA performance (ISO 27001 / SOC 2).
  5. Cloud Carrier: Telecom/network intermediary transporting secure connectivity between consumer and provider.
Exam Tip: Memorize C-P-B-A-C (Consumer, Provider, Broker, Auditor, Carrier) and list the 3 Broker roles (Intermediation, Aggregation, Arbitrage) for a guaranteed 10/10.

2023–24 · Q4 Unit IV 10 Marks

4. Discuss the importance of Identity and Access Management (IAM) in cloud security. How does IAM help manage user permissions and access control?
View Full-Mark 10M Answer
1. Definition

Identity and Access Management (IAM) is the cloud security framework of policies, identities, and verification tools ensuring that only authenticated and authorized users or services can access specific cloud resources at the right time.

2. Importance of IAM in Cloud Security
  • Identity is the New Perimeter: Because cloud APIs are reachable over the public internet, traditional office firewalls are insufficient—Zero Trust starts with IAM.
  • Multi-Tenant & Team Isolation: Prevents developers, interns, or compromised apps from reading or deleting sensitive production databases.
  • Regulatory Compliance: Produces tamper-proof access trails required for ISO 27001, SOC 2, PCI DSS, and GDPR.
3. How IAM Manages Permissions & Access Control (I-A-A-A Flow)
  1. Authentication (AuthN): Verifies identity via passwords, Multi-Factor Authentication (MFA), and federated Single Sign-On (SAML 2.0 / OAuth 2.0).
  2. Authorization (RBAC & ABAC): Evaluates fine-grained JSON policies specifying exact Effect (Allow/Deny), Action, and Resource.
  3. Principle of Least Privilege: Grants each user/service only the minimum permissions necessary for their role.
  4. Temporary IAM Roles: Cloud services assume short-lived auto-rotating tokens instead of storing hardcoded credentials in source code.
  5. Central Lifecycle & Auditing: Instantly revokes offboarded employee access across all accounts and records every API action in immutable logs (AWS CloudTrail).

MapReduce is Hadoop's distributed parallel programming model that processes terabytes to petabytes of data across clusters of commodity hardware by transforming data through <Key, Value> pairs in two main phases: Map and Reduce.

2. MapReduce Execution Diagram (WordCount Example)
3. Step-by-Step Contribution to Big Data in Hadoop
  • Massive Horizontal Parallelism: Splits huge HDFS files into 128 MB blocks processed concurrently by hundreds of Mappers on cheap commodity servers.

2023–24 · Q6 Unit I 10 Marks

6. Explain the concept of on-demand provisioning. How does it enhance the scalability of cloud resources?
View Full-Mark 10M Answer
1. Concept of On-Demand Provisioning

On-Demand Provisioning is the automated, self-service allocation of cloud resources (VMs, storage, networks, databases) instantaneously upon user or application request—without manual provider intervention—and automatic release once the workload finishes.

2. 5-Step Automated Provisioning Lifecycle
  1. Self-Service Request: User console, Terraform script, or autoscaler calls the cloud API (e.g., request 4 vCPUs, 16 GB RAM).
  2. IAM Auth & Quota Check: Cloud verifies caller identity, RBAC permissions, and account limits.
  3. Orchestrator Scheduling: Placement engine picks a physical host with available compute/RAM capacity.
  4. Hypervisor Provisioning: Hypervisor boots the VM image, attaches virtual EBS storage, and assigns a VPC IP in under 60 seconds.
  5. Metering & Deprovisioning: Usage is metered per second; terminating the VM immediately returns capacity to the shared pool.
3. How It Enhances Scalability
  • Eliminates Weeks of Hardware Procurement: Scale out in seconds instead of waiting for physical servers to ship and rack.
  • Drives Automated Horizontal Scaling: Paired with load balancers and CloudWatch alerts, web tiers expand 10× during peak events (e.g., IRCTC Tatkal, Flipkart Big Billion Days).
  • Supports Elastic Scale-Down: Releases excess instances when traffic falls, preventing costly over-provisioning.
  • Multi-Region Expansion: Deploy replicas globally in minutes to keep latency low worldwide.

2023–24 · Q7 Unit I 10 Marks

7. Explain the importance of Distributed Computing in the context of cloud systems. Also list the essential characteristics of cloud computing as defined by NIST.
View Full-Mark 10M Answer
1. Importance of Distributed Computing in Cloud Systems

Distributed Computing connects multiple independent computers over a network (each with its own local memory and OS) that coordinate via message passing to present a single coherent system. It is the backbone of cloud computing because:

  • Horizontal Scalability: No single machine can serve millions of users; clouds distribute load across thousands of commodity servers.
  • Fault Tolerance & High Availability: Replicating data and stateless services across servers and Availability Zones ensures zero downtime when hardware fails (governed by the CAP Theorem).
  • Global Low Latency: Distributed data centers and CDNs serve requests from the region closest to each user.
  • Distributed Big Data & Storage: Enables petabyte-scale object storage (Amazon S3) and distributed processing (Hadoop/HDFS).
2. Five Essential Characteristics of Cloud Computing (NIST SP 800-145 · Mnemonic: O-B-R-R-M)
  1. On-Demand Self-Service: Provision compute/storage automatically via console/API without human interaction.
  2. Broad Network Access: Accessible over the internet from heterogeneous devices (phones, laptops, workstations).
  3. Resource Pooling: Shared multi-tenant hardware dynamically assigned with location independence.
  4. Rapid Elasticity: Scales outward and inward rapidly (often automatically) to match real-time demand.
  5. Measured Service: Automatic metering of CPU, storage, and bandwidth for transparent pay-per-use billing.

2023–24 · Q8 Unit II 10 Marks

8. Discuss the key virtualization structures, such as full virtualization and paravirtualization. How do they impact system performance and efficiency?
View Full-Mark 10M Answer
1. Key Virtualization Structures
  • Full Virtualization: Emulates complete underlying hardware so an unmodified guest OS (Windows, Linux) runs unaware of the hypervisor. Non-virtualizable sensitive CPU instructions are intercepted and rewritten at runtime via binary translation (or hardware-assisted Intel VT-x/AMD-V).
  • Paravirtualization: The guest OS kernel is explicitly modified to be virtualization-aware. Instead of trapping slow sensitive instructions, the guest invokes lightweight direct APIs called hypercalls into the hypervisor (e.g., Xen PV, virtio I/O drivers).
2. Performance & Efficiency Comparison
CriteriaFull VirtualizationParavirtualizationHardware-Assisted (VT-x/AMD-V)
Guest OS Modified?No (any OS runs as-is).Yes (Linux/open-source kernel).No (any unmodified OS).
MechanismSoftware binary translation.Direct hypercalls to VMM.Hardware VMX root/non-root modes.
PerformanceModerate CPU overhead.High efficiency & fast I/O.Near-native speed (modern standard).
PortabilityMaximum OS compatibility.Tied to modified kernel version.Maximum compatibility + speed.

Conclusion: Modern clouds (AWS Nitro, KVM, VMware ESXi) combine Hardware-Assisted CPU virtualization for unmodified OS support with paravirtualized I/O (virtio) for peak throughput and efficiency.

Physical server recovery required purchasing identical backup hardware and manually reinstalling OS and apps over days. Virtualization encapsulates an entire server (OS + libraries + apps + data) into portable image files, enabling automated recovery in minutes.

2. RPO & RTO Recovery Timeline
3. Four Core Mechanisms & Role in Business Continuity
  1. Hardware Independence: Replicated VM files boot on any physical host at a remote cloud region—no matching server brand required.

2023–24 · Q11 Unit III 10 Marks

11. Explain the features and functionalities of Amazon S3 (Simple Storage Service). How does it support scalable and secure storage in the cloud?
View Full-Mark 10M Answer
1. Overview

Amazon S3 is AWS's fully managed Object Storage Service that stores unstructured files as Objects (Data + Metadata + Unique Key, up to 5 TB each) inside globally uniquely named Buckets accessed via HTTP/HTTPS REST APIs.

2. Key Features & Functionalities
  • 11 Nines Durability (99.999999999%): Automatically replicates every object across at least 3 physically separate Availability Zones (AZs).
  • Storage Classes & Lifecycle Policies: Automates cost savings across S3 Standard (hot), Intelligent-Tiering, Standard-IA (infrequent), and S3 Glacier / Deep Archive (long-term compliance archiving).
  • Versioning & Cross-Region Replication (CRR): Keeps historical versions to recover from accidental deletion or ransomware and replicates across regions for DR.
  • Strong Read-After-Write Consistency & Event Triggers: Immediate visibility after PUT/DELETE; hosts static websites and triggers AWS Lambda functions automatically on uploads.
3. How S3 Guarantees Scalability & Security
  • Scalability: Flat object namespace scales seamlessly from bytes to exabytes with zero capacity planning and high parallel throughput.
  • Security: Enforces Block Public Access by default, fine-grained IAM & Bucket Policies, Pre-signed URLs for temporary access, TLS/HTTPS in transit, and Server-Side Encryption (SSE-S3, SSE-KMS) at rest.

2023–24 · Q14 Unit V 10 Marks

14. Define Hadoop and explain its role in distributed computing. How does it handle large-scale data processing?
View Full-Mark 10M Answer
1. Definition

Apache Hadoop is an open-source distributed computing framework written in Java that stores and processes massive datasets (terabytes to petabytes) reliably across clusters of inexpensive commodity hardware.

2. Core Modules & Role in Distributed Computing
  • HDFS (Storage): Distributed Master–Slave file system (NameNode + DataNodes).
  • MapReduce (Processing): Parallel batch processing framework using <Key, Value> pairs.
  • YARN (Resource Manager): Allocates cluster CPU/RAM containers dynamically across jobs.
  • Hadoop Common: Shared Java libraries and utilities.
3. How Hadoop Handles Large-Scale Data Processing
  1. 128 MB Block Splitting & 3× Rack-Aware Replication: Splits massive files into 128 MB blocks copied across 3 DataNodes (2 on one rack, 1 on another) for automatic fault tolerance.
  2. Data Locality ("Move Compute to Data"): YARN runs Map tasks directly on the DataNodes storing the blocks—preventing network congestion.
  3. Parallel Map → Shuffle & Sort → Reduce: Processes blocks concurrently across hundreds of nodes, groups intermediate keys, aggregates final results, and automatically restarts any failed task.

2024–25 · Q14 Unit V 7 Marks

14. What is HDFS, and how does it ensure reliable storage in a distributed environment?
View Full-Mark 7M Answer
1. Definition & Master–Slave Architecture

HDFS (Hadoop Distributed File System) is Hadoop's distributed, fault-tolerant storage layer designed to store petabytes reliably on cheap commodity hardware using a NameNode (Master) holding metadata in RAM and DataNodes (Slaves) storing 128 MB data blocks on local disks.

2. Four Mechanisms Ensuring Reliable Storage
  1. Triple Block Replication (Factor = 3): Every 128 MB block is stored on 3 separate DataNodes so a disk failure never causes data loss.
  2. Rack Awareness: Places 2 replicas on Rack A and the 3rd replica on Rack B—surviving even an entire rack power/switch failure.
  3. Heartbeats & Auto-Re-Replication: DataNodes send heartbeats every 3 seconds; if a node goes silent, NameNode marks it dead and automatically creates replacement replicas on healthy nodes.
  4. Checksums & Write-Once-Read-Many (WORM): Verifies block integrity via checksums on every read to detect and automatically heal silent disk corruption.

15. Explain the risks of insider threats in cloud computing, and how can they be mitigated?
View Full-Mark 7M Answer
1. Risks of Insider Threats

An Insider Threat originates from an authorized person (employee, contractor, or rogue cloud admin) misusing legitimate credentials—making it harder to detect than external attacks:

  • Data Exfiltration & Espionage: Downloading customer PII or proprietary source code past perimeter firewalls.
  • Malicious Sabotage: Deleting production VMs, S3 buckets, or backup snapshots.
  • Negligent Misconfiguration: Careless insiders leaving databases publicly exposed or committing API keys to public repos.
2. Five Key Mitigation Strategies
  1. Principle of Least Privilege & RBAC: Limit every user to strictly the minimum permissions needed for their role.
  2. Zero Trust & Hardware MFA: Require MFA and Just-In-Time (JIT) temporary elevation for admin tasks.

  4. Customer-Managed Encryption (BYOK): Encrypt cloud data with customer-held keys so even rogue cloud admins cannot read it.
  5. Immutable Audit Logs & Rapid Offboarding: Log all API calls in WORM storage (AWS CloudTrail), alert on anomalous bulk downloads, and revoke SSO instantly on employee exit.

1. Explain underlying principles of parallel and distributed computing and their importance in cloud computing.
View Full-Mark 7M Answer
1. Underlying Principles
  • Parallel Computing: Multiple cores inside a single machine share global RAM to run decomposed tasks simultaneously (Data & Task Parallelism; classified by Flynn's Taxonomy — SISD, SIMD, MISD, MIMD; speedup bounded by Amdahl's Law: S(N) = 1 / [(1 − p) + p/N]).
  • Distributed Computing: Multiple autonomous computers connected over a network (private local RAM each) coordinate via message passing (TCP/IP, RPC, HTTP) to act as a unified system (governed by the CAP Theorem: trade-off between Consistency, Availability, and Partition Tolerance).
2. Importance in Cloud Computing
  1. High Compute Performance: Multi-core VMs and GPUs accelerate AI/ML training, analytics, and video transcoding.
  2. Massive Horizontal Scalability: Distributed clusters allow AWS, Azure, and GCP to scale across thousands of commodity servers.
  3. Fault Tolerance & High Availability: Distributed replication keeps apps online even when individual nodes crash.
  4. Big Data Processing: Powers distributed storage (HDFS, S3) and parallel batch engines (MapReduce, Spark).

8. Describe REST-based web services and explain their architectural principles.
View Full-Mark 7M Answer
1. Description of REST-Based Web Services

REST (Representational State Transfer) is a lightweight, resource-oriented architectural style over HTTP. Every entity is a resource identified by a URI (e.g., /api/orders/101) and exchanged as JSON/XML representations via standard HTTP verbs (GET, POST, PUT, DELETE).

2. Six Architectural Principles (Constraints) of REST
  1. Client–Server Separation: UI (client) and data/logic (server) evolve independently.
  2. Statelessness: Every request carries complete authentication/context; the server stores no client session state—making horizontal cloud scaling seamless.
  3. Cacheability: Responses specify caching rules (Cache-Control) to cut latency and backend load.
  4. Uniform Interface: Consistent resource URIs, standard HTTP verbs, and standard status codes (200 OK, 201 Created, 404 Not Found).
  5. Layered System: Clients interact cleanly through load balancers, API gateways, and CDNs without knowing internal server layout.
  6. Code on Demand (Optional): Servers may send executable scripts (e.g., JavaScript) to extend client behavior.

3. Working of MapReduce
  1. Input Splitting: Splits HDFS files into parallel chunks assigned to Mappers on local DataNodes.
  2. Map Phase: Parses records and outputs intermediate <Key, Value> pairs (e.g., (Cloud, 1)).
