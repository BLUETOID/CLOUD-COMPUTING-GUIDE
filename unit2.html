01 / Service Architecture (Asked in 2023–24 & 2025–26)

Service-Oriented Architecture (SOA) & Microservices

Simple Definition

Service-Oriented Architecture (SOA) is a software design paradigm where large applications are built by assembling independent, self-contained, reusable services that communicate over a network through standardized API contracts (such as HTTP/REST or SOAP). Each service performs a discrete business capability (e.g., Login, Payment, Inventory).

Six Core Principles of SOA

  • Loose Coupling: Consumers depend only on the public API contract, not on the service's internal database or programming language.
  • Reusability: A single Authentication or Notification service is shared across web apps, Android/iOS apps, and partner portals.
  • Interoperability: A Python frontend seamlessly calls a Java or Go backend using standard HTTP + JSON/XML.
  • Discoverability: Services publish machine-readable descriptions (OpenAPI / WSDL) so teams can discover and reuse them.
  • Composability: Small atomic services can be orchestrated into larger workflows (e.g., Order = Auth + Inventory + Payment + Shipping).
  • Autonomy & Statelessness: Each service controls its own logic and avoids storing unnecessary client session state.

02 / Web Services (Asked in 2023–24 & 2025–26)

REST-Based Web Services & SOAP vs REST

REST (Representational State Transfer), defined by Roy Fielding (2000), is a lightweight architectural style for networked applications built on top of HTTP. Every data entity is modeled as a resource addressed by a clean URI (e.g., https://api.shop.com/orders/42) and exchanged as JSON or XML representations.

The 6 Architectural Principles (Constraints) of REST

  1. Client–Server Separation: User interface (client) and data storage/business logic (server) are decoupled so mobile apps, web browsers, and backend teams evolve independently.
  2. Statelessness: Every request must carry all authentication and context (e.g., JWT bearer token). The server stores no client session state between calls—making horizontal scaling behind a load balancer effortless.
  3. Cacheability: Responses explicitly declare caching rules (Cache-Control: max-age=300) so CDNs and browsers reuse responses, reducing server load and latency.
  4. Uniform Interface: Uses standard HTTP verbs and status codes uniformly across all resources:
    • GET (Read) · POST (Create) · PUT (Full Update) · PATCH (Partial Update) · DELETE (Remove)
    • Standard Status Codes: 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 404 Not Found, 500 Server Error.
  5. Layered System: Clients communicate cleanly through intermediate proxies, API gateways, firewalls, or load balancers without knowing the internal backend topology.
  6. Code on Demand (Optional): Servers can temporarily extend client functionality by sending executable scripts (e.g., JavaScript).

03 / Complex Integration (Asked in 2025–26)

Systems of Systems (SoS)

A System of Systems (SoS) is a large-scale collaborative system created by integrating multiple operationally and managerially independent systems so they deliver an emergent capability that none could achieve individually.

  • Real-World Example: A travel aggregator (MakeMyTrip) connects independent airline reservation systems (IndiGo, Air India), hotel booking engines, UPI/Visa payment gateways, and SMS providers into one unified itinerary booking flow.
  • Maier's 5 Characteristics of SoS:
    1. Operational Independence: Each constituent system can still run usefully on its own.
    2. Managerial Independence: Each system is owned, funded, and upgraded by a separate organization.
    3. Emergent Behavior: Combining them produces brand-new capabilities (e.g., comparing 20 airlines + hotels in 1 second).
    4. Evolutionary Development: Subsystems are added, replaced, or updated continuously without stopping the whole SoS.
    5. Geographic Distribution: Subsystems operate across different regions/clouds and exchange only messages over networks.

04 / Event-Driven Cloud Messaging

Publish/Subscribe (Pub/Sub) Model

Publish/Subscribe decouples event producers (Publishers) from consumers (Subscribers) through an intermediary Message Broker (e.g., Apache Kafka, RabbitMQ, AWS SNS, Google Pub/Sub). Publishers emit events to a named Topic without knowing who is listening; the broker fans out copies asynchronously to all subscribed services.

05 / Core Cloud Engine (Asked in 2024–25 & 2025–26)

Basics of Virtualization & How It Enables Cloud

Virtualization abstracts physical computing resources (CPU, RAM, storage, network) into logical virtual environments using a software layer called a Hypervisor. This allows a single physical server to run multiple isolated Virtual Machines (VMs) concurrently, each running its own Guest OS.

Four Ways Virtualization Enables Cloud Computing

  1. Multi-Tenancy & Resource Pooling: One 64-core physical server is sliced into 20 isolated VMs rented to 20 separate organizations, lifting hardware utilization from ~15% to 75%+.
  2. Rapid Provisioning & Elasticity: Cloning a software VM image takes seconds—making on-demand self-service and autoscaling possible.
  3. Hardware Independence & Live Migration: Because a VM is encapsulated as portable disk/config files, it can be live-migrated across physical hosts with zero downtime.
  4. Fault & Security Isolation: A kernel panic or malware inside Tenant A's VM cannot crash Tenant B's VM on the same host.

Popek–Goldberg Virtualization Theorem (Bonus Marks!)

When Is a CPU Architecture Efficiently Virtualizable?

A computer architecture is classically virtualizable if all sensitive instructions (instructions that read or change hardware/privilege state) are a strict subset of privileged instructions (instructions that automatically trap to the hypervisor when executed in user mode). Legacy x86 CPUs had 17 sensitive unprivileged instructions, requiring software binary translation until Intel VT-x and AMD-V added hardware virtualization support.

5 Implementation Levels of Virtualization

  1. ISA Level (Instruction Set Architecture): Emulates another CPU's instruction set in software (e.g., QEMU running ARM on x86). Maximum portability, slowest speed.
  2. Hardware Abstraction Level (HAL): Hypervisor virtualizes physical CPU, RAM, and I/O directly (ESXi, KVM, Xen). Standard for public IaaS clouds.
  3. Operating System Level: Multiple isolated containers share one host kernel (Docker, LXC). Highest density and fastest boot.
  4. Library Support Level: Intercepts API calls between applications and OS libraries (e.g., WINE running Windows apps on Linux).
  5. Application Level: Virtualizes a single application runtime (e.g., JVM executing Java bytecode across any OS).

07 / Resource Virtualization Mechanisms (Asked in 2023–24 & 2024–25)

CPU, Memory, I/O & Network Virtualization

1. CPU Virtualization

Each VM is assigned one or more Virtual CPUs (vCPUs). The hypervisor's CPU scheduler time-slices vCPUs across physical cores, storing each vCPU's register state in a hardware VMCS (Virtual Machine Control Structure). With Intel VT-x / AMD-V, user instructions run directly on silicon while privileged instructions trigger a VM Exit to the hypervisor—enabling safe CPU overcommitment (e.g., 16 vCPUs on 8 physical cores).

  • I/O Virtualization Modes: (1) Full Emulation (hypervisor mimics an Intel NIC in software — universal but slow), (2) Paravirtualized I/O (virtio) (shared memory ring buffers — fast & standard in KVM/AWS), and (3) Direct Assignment (PCI Passthrough / SR-IOV) (VM accesses physical NIC/GPU directly for near-bare-metal speed).
  • Network Virtualization (SDN & VXLAN): Virtual switches (Open vSwitch) and overlay tunnels (VXLAN / GENEVE) decouple logical tenant networks from physical cables, enabling cloud providers to spin up isolated Virtual Private Clouds (VPCs), virtual routers, and load balancers via APIs in seconds.

08 / Business Continuity (Asked in 2023–24)

Virtualization Support for Disaster Recovery

Virtualization encapsulates an entire server (OS, libraries, apps, data) into portable software files—eliminating the need for identical physical backup hardware and slashing recovery time from days to minutes.
