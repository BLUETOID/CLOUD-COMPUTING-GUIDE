01 / System Stack (Asked in 2025–26)

Layered Cloud Architecture Design

A cloud platform is engineered as a five-layer vertical stack (from physical hardware at the bottom to end-user devices at the top), reinforced by a cross-cutting management and security plane that governs every layer.

Figure 3.1 — 5-Layer Cloud Architecture Stack Must-Draw Exam Diagram
L5
Client / Access Layer Web browsers, mobile apps, thin clients, CLI/REST APIs connecting via HTTPS/TLS.
L4
Application Layer (SaaS) Ready-to-use multi-tenant software: Gmail, Salesforce CRM, Microsoft 365, Zoom.
L3
Platform Layer (PaaS) Managed runtimes, SDKs, databases, CI/CD, message queues (Google App Engine, Heroku).
L2
Infrastructure & Virtualization Layer (IaaS) Hypervisors (KVM, ESXi, Xen), VMs, containers, virtual storage (EBS) & SDN/VPCs.
L1
Physical / Hardware Layer Data center server racks, SAN/NAS arrays, fiber switches, UPS power & cooling.

Cross-Cutting Plane

  • Identity & Access (IAM)
  • Encryption & Firewalls
  • Monitoring & Telemetry
  • Metering, Billing & SLAs
  • Orchestration & Autoscaling

Why Layered Architecture Is Crucial

  • Clean Abstraction: Each layer hides hardware/implementation complexity from the layer above it.
  • Independent Evolution: Data center engineers can replace faulty Layer 1 SSDs without interrupting Layer 4 SaaS users.
  • Clear Fault & Security Boundaries: Makes enforcing Shared Responsibility and troubleshooting outages far simpler.

04 / IaaS · PaaS · SaaS (Asked Every Year)

Cloud Service Models & Shared Responsibility

  • IaaS (Infrastructure as a Service): Virtualized compute, storage, and networking. Customer controls OS, middleware, and apps. Examples: AWS EC2, Azure VMs, Google Compute Engine, OpenStack.
  • PaaS (Platform as a Service): Managed OS, language runtimes, databases, and auto-scaling. Customer writes and deploys code only. Examples: Google App Engine, Heroku, AWS Elastic Beanstalk.
  • SaaS (Software as a Service): Complete multi-tenant web applications accessed via browser. Provider manages everything; customer manages users & data. Examples: Gmail, Salesforce CRM, Microsoft 365, Zoom.

05 / Specialized Models (Asked in 2024–25)

Serverless (FaaS), CaaS, Cloud CRM & Collaboration

  • Serverless Computing (FaaS): Enhances PaaS by running stateless functions strictly on events (HTTP request, S3 upload, DB trigger). Provides scale-to-zero ($0 cost when idle) and millisecond billing (AWS Lambda, Azure Functions, Google Cloud Functions).
  • CaaS (Communication as a Service): Cloud-hosted VoIP, video conferencing, messaging, and virtual PBX without physical telecom hardware (Twilio, Zoom, Microsoft Teams, Cisco Webex).
  • Cloud CRM: Centralizes customer contacts, sales pipelines, marketing automation, and support analytics accessible anywhere (Salesforce, HubSpot, Zoho CRM).
  • Cloud Email & Office Suites: Gmail / Google Workspace and Outlook / Microsoft 365 provide real-time multi-user co-authoring, automatic version history, AI spam filtering, and unified collaboration for both remote (essential primary workspace) and in-office teams (eliminates USB drives & conflicting file copies).

06 / Engineering Trade-Offs

Six Architectural Design Challenges

  1. Service Availability & Business Continuity: Eliminating single points of failure across Availability Zones and Regions.
  2. Data Lock-In & Portability: Overcoming proprietary APIs and high egress fees when migrating between providers.
  3. Data Confidentiality & Auditability: Protecting multi-tenant data via TLS/AES-256 and meeting GDPR/ISO/SOC 2 audits.
  4. Data Transfer Bottlenecks: Moving terabytes over WAN links is slow (solved via AWS Snowball physical appliances or Direct Connect).
  5. Performance Unpredictability ("Noisy Neighbor"): Shared CPU/I/O contention from co-located tenants degrading tail latency.
  6. Debugging Large-Scale Distributed Systems: Tracing bugs across hundreds of asynchronous microservices requires distributed tracing tools.

Durability vs Availability: Durability = probability your data is never lost/corrupted (S3: 99.999999999%). Availability = probability you can access it right now without downtime (S3 Standard: 99.99%).

08 / Case Study (Asked in 2023–24)

Amazon S3 (Simple Storage Service) Deep Dive

Amazon S3 is AWS's flagship object storage platform storing objects (up to 5 TB each) inside globally uniquely named Buckets, automatically replicated across at least 3 Availability Zones for 11 nines (99.999999999%) durability.
